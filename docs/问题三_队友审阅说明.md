## 当前不能写入论文的结论

`solve_q3_scheme2_joint.py` 曾在当前候选任务库和实现约束下返回 `INFEASIBLE`。这只能说明该**原型模型**无解，不能证明原题或方案 2 无解，原因包括：

- 仅对部分高冲突航次补充了连续驻留候选，任务库不完整；
- 为控制规模，原型含“同覆盖集合保留最多 8 条代表列”的工作集截断；该截断不保可行性；
- 尚未实现“状态合并 + 两阶段决策”的正式求解框架。

因此，`outputs/q3/scheme2/formal/` 下的不可行 JSON 都是**实现诊断**，不得引用为竞赛结果。

## 建议的重构方向

采用“二阶段决策 + 状态合并”的求解流程：

1. 第一阶段生成并选择连续驻留服务任务块，保留少量 Pareto 候选组合；
2. 第二阶段以 CP-SAT 排程运输时序、服务任务和资源；
3. 对同型中继机与同型组件，用排序后的释放时刻表示状态，消除 R01/R02 和组件编号的对称搜索；
4. 每次得到候选解后，以 0.25 秒步长重放全部链路，而不是由离散网格直接宣称连续通信。
